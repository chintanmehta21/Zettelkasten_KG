# Known-failing live tests — the burn-down baseline.
#
# WHY THIS FILE EXISTS
# --------------------
# `pytest --live` was red and unnoticed from 2026-05-31 to 2026-08-01 (248
# failures). A permanently-red suite protects nothing: nobody can tell a new
# regression from the standing noise, so everyone stops looking. That is how
# two rotted deploy fixtures stayed invisible for two months and eventually
# took production down.
#
# The industry answer is a ratchet, not a heroic fix-everything push:
#   1. record the current failures as an explicit, committed baseline;
#   2. make CI fail only on NEW failures;
#   3. burn the baseline down on a clock, and never let it grow.
#
# Sources for the shape of this file:
#   * Software Engineering at Google, Ch.23 (Continuous Integration) — Google's
#     Takeout team disabled failing tests tagged with a bug number to keep the
#     suite green, then automated re-enablement.
#   * Dropbox "Athena" (2019-05-22) — auto-quarantine out of presubmit, keep
#     running post-submit, notify rather than auto-revert.
#   * GitLab testing guide (Unhealthy tests) — a quarantined test MUST carry a
#     tracking reference "so it doesn't stay in quarantine forever".
#   * Martin Fowler, "Eradicating Non-Determinism in Tests" (2011-04-14) —
#     quarantine needs a hard cap or a time limit, "otherwise you might as well
#     get rid of all the tests".
#
# HOW IT WORKS
# ------------
# tests/conftest.py reads this file and applies `xfail` to each listed node id.
#   strict  (default) -> an unexpected PASS FAILS the run. That is the point:
#                        the moment someone fixes one, CI tells you to delete
#                        the line. The list cleans itself.
#   flaky            -> non-strict. Use ONLY for tests verified to pass in
#                        isolation and fail under load. Never use it to hide a
#                        deterministic failure.
#
# Format:  <pytest node id>  [# flaky] [# reason]
# Lines beginning with # are comments.
#
# RULES
#   * This file may SHRINK freely. Growing it needs a deliberate decision and
#     should be justified in the PR description.
#   * `skip` is never the right primitive here — it does not execute the test
#     body, so a skipped test tells you nothing, ever. `xfail` runs it.
#   * Do NOT add global `--reruns`. These tests call real Gemini; reruns
#     multiply paid API usage to paper over a classification you already have.
#
